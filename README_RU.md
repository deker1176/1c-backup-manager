# v5.3.0 — управляемое ночное освобождение базы 1С через IIS

**Сначала сделайте контрольную резервную копию всех баз и согласуйте окно простоя.** Для файловой базы на странице задания «Отключение пользователей» включите «Автоматически завершать пользователей» и отдельно «Разрешаю временно останавливать указанный пул IIS». Впишите **точное имя разрешённого пула** (например, `DefaultAppPool`), окно (по умолчанию 23:00–06:00). Ранее сохранённые задачи **не получают это разрешение автоматически**.

Порядок при заблокированном `.dt`: две обычные попытки `DumpIB`, ожидание; затем точная проверка опубликованной файловой базы (`File=` в `default.vrd`), соответствия разрешённому пулу и времени; независимое аварийное восстановление пула регистрируется в Windows Task Scheduler **от SYSTEM до остановки IIS**. Программа останавливает только этот пул, получает эксклюзивный дескриптор `CreateFileW` на `1Cv8.1CD` (`share=0` на всю длительность копирования), сверяет длину и SHA256, после чего **в любом случае пытается снова запустить IIS в `finally`**. Только после восстановления IIS выполняется `1cv8.exe DESIGNER /DumpIB` из временного файлового снимка, не из рабочей базы.

Если невозможно получить эксклюзивный доступ к `1Cv8.1CD` после остановки IIS, нет места, не удалось зарегистрировать восстановление или не совпали пул/время, копирование прекращается и журнал фиксирует ошибку. Не выполняется остановка других пулов или закрытие SMB-дескрипторов. Обычное завершение работы очищает временную папку; в случае аварии ОС/процесса может потребоваться ручная уборка каталога `1cbm_stage_*` в папке бэкапов. Если процесс аварийно завершается при остановленном IIS, независимое задание Планировщика пытается запустить разрешённый пул примерно через 20 минут (на машине с работающим Task Scheduler); контроль восстановления обязателен.

**Перед первым включением на рабочем сервере:** запустите GUI от администратора и сделайте пробный запуск при отсутствии критичных операций в веб-базах. Убедитесь по журналу в последовательности `IIS остановлен → снимок 1Cv8.1CD → IIS восстановлен → DumpIB из снимка`, а также в наличии готового `.dt` и возможности его восстановления в отдельную тестовую базу. Если Windows Task Scheduler не даёт зарегистрировать задание от SYSTEM, программа не должна останавливать пул.

**Предупреждение:** остановка общего IIS-пула прерывает работу всех сайтов и 1С-баз в нём, несохранённые изменения могут быть потеряны. Планировщик аварийного восстановления не гарантирует запуск, если Windows или сама служба Планировщика недоступны. Сборка и тесты не заменяют проверку на тестовой файловой базе под Windows.

Документация: https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Administration/Misc/Tips_on_infobase_backup/ ; https://learn.microsoft.com/en-us/iis/get-started/getting-started-with-iis/getting-started-with-appcmdexe

# Версия 5.2 — диагностика файловых баз и безопасный поиск клиентов

- **Без зависимости от УНФ/БСП и без изменения конфигурации 1С:** Windows Restart Manager проверяет процессы, открывшие именно файл \`1Cv8.1CD\`. Если найден локальный клиент \`1cv8.exe\`/\`1cv8c.exe\`/\`1cv8s.exe\`, его можно целево завершить после включения существующего флажка «Автоматически завершать пользователей». Сохраняется повторная проверка имени процесса, командной строки и времени запуска перед закрытием.
- При ошибке исключительной блокировки автоматически собирается диагностика Windows, IIS и SMB. IIS-публикации сопоставляются по реальной строке подключения \`File=\` из \`default.vrd\`, включая случай \`Default Web Site/unf\` в \`DefaultAppPool\`.
- **Общие пулы IIS/Apache не останавливаются**. По технологической архитектуре 1С они могут обслуживать несколько баз одновременно. Универсального безопасного завершения только одной веб-базы в общем процессе Windows нет; при таком подключении автоматическая принудительная выгрузка может остаться невозможной. Нужен выход пользователей или инфраструктурно изолированный способ управления конкретным соединением.
- Диагностика SMB не закрывает удалённые файловые дескрипторы. Для удалённых клиентских процессов прежние WinRM/алиасы остаются опциональной возможностью; никакого глобального \`taskkill\`, \`iisreset\`, \`Stop-Process w3wp\` нет.
- При неудачном \`DumpIB\` частичный \`.dt\` удаляется из целевой папки, чтобы не принять повреждённый/неполный файл за резервную копию.
- Добавлен набор тестов \`test_v52.py\` и Windows EXE сборка в CI. Проверка настоящих открытых сеансов на сервере требует отдельного теста Windows; сборка EXE сама по себе не подтверждает их отключение.
- При обновлении менять **только EXE**; сохранить \`config.json\`, \`secrets.dat\`, \`scheduler_state.json\`, \`task_history/\` и резервные копии.

Источники: [архитектура файлового режима 1С](https://v8.1c.ru/platforma/faylovyy-variant-raboty/), [рекомендации по копированию](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Administration/Misc/Tips_on_infobase_backup/).

# Версия 5.1 — активные задачи и подробный журнал запусков

- Вкладка **«Активные задачи»** теперь показывает таблицу: имя задания, следующий запуск, предыдущий запуск и состояние. Большие логи в этой вкладке больше не отображаются.
- Вкладка **«Журнал задач»** сохраняет историю **всех новых попыток**, а не только последний результат. Двойной щелчок по записи открывает отдельное окно с логом именно этого запуска. Там же есть кнопка копирования журнала.
- История каждого запуска хранится в `task_history/` рядом с EXE: отдельные файлы JSON и LOG, в том числе для заданий службы Windows. Настройка «Хранить журналы» применяется и к ним. Старые версии не сохраняли полный журнал по запускам; их последняя запись показывается без подробностей.
- В файловой базе на вкладке «Отключение пользователей» убраны технические переключатели способов. Есть один флажок «Автоматически завершать пользователей» и время ожидания. При наличии дополнительной информации о ПК или сетевых путях программа использует её.
- **Ограничение:** для файловой базы с клиентами через IIS/Apache или с удалённых ПК нельзя универсально и безопасно завершить все сеансы без доступа к соответствующим ПК или выделенному веб-ресурсу. Программа не останавливает общие IIS/Apache-службы и не убивает процессы других баз.
- `config.json` и `secrets.dat` при замене EXE не перезаписывать.

# 1C Backup Manager v4.8 — уведомления в MAX

## Новое: MAX Bot API

В **Сервис → Параметры программы → Отчеты** появился раздел **MAX Bot API**:

- **Bot Token MAX** — токен бота, сохраняется только в шифрованном Windows DPAPI `secrets.dat` (тот же пользователь Windows, что и у службы).
- **Тип ID**: `chat_id` (группа/канал) или `user_id` (личное сообщение).
- **ID получателя MAX** — целочисленный ID, а не никнейм бота.
- Кнопка **Тест MAX** — отправляет одно тестовое сообщение по указанным, в том числе ещё не сохранённым, реквизитам.

У каждой задачи в разделе **«Отправка отчетов»** добавлена галочка **«Отправлять отчет в MAX»**. Как и для Telegram и SMTP, отдельно включаются отчёты об успехе и об ошибке. Для задачи **«Отправка отчетов»** можно оставить только MAX, чтобы рассылать сводку последних результатов заданий. Все новые галочки выключены по умолчанию.

### Как получить ID и токен

1. Создайте/настройте бота через [MAX для разработчиков](https://dev.max.ru/docs/chatbots/bots-nocode/) (этот раздел посвящён конструкторам без кода; для прямой отправки нужен действующий **Bot API Token** из настроек бота).
2. Для группового чата/канала добавьте бота и возьмите `chat_id` из событий `bot_added`/`bot_started` через webhook/subscriptions или long polling `GET /updates`. Официальная инструкция: https://dev.max.ru/docs-api/methods/GET/chats
3. Для личного сообщения укажите `user_id` получателя, если он известен и бот может ему писать.
4. Введите токен и ID, выберите правильный тип ID, нажмите **Тест MAX**. После успешного теста сохраните настройки и включите MAX в нужном задании.

Реализация использует **POST `https://platform-api2.max.ru/messages?chat_id=...`** (или `?user_id=...`) с заголовком **`Authorization: <token>`**, JSON-телом `{"text": "..."}` и проверкой TLS. Ссылка на API: https://dev.max.ru/docs-api/methods/POST/messages

> **Важно:** официальный MAX рекомендует корректно настроить доверенные сертификаты (в том числе сертификат Минцифры), если требуется. Не отключайте TLS-проверку сертификатов. Бот должен иметь право писать получателю.

### Обработка ошибок

Ошибки доставки MAX пишутся в журнал, но **не меняют статус успешно созданной резервной копии**. Только отдельная задача «Отправка отчетов» считается ошибочной при неудачной доставке. Токен не записывается в конфигурацию/журнал. При старте со старым `config.json` и `secrets.dat` уведомления MAX автоматически отключены.

### Обновление с v4.7

1. Сохраните старый EXE, `config.json`, `secrets.dat`, `scheduler_state.json`.
2. Остановите службу `OneCBackupManager` и закройте GUI.
3. Запустите `build_windows.bat`, замените только EXE. Не копируйте пример конфига поверх своего.
4. Проверьте вкладку «Отчеты», нажмите «Тест MAX», затем настройте отдельную задачу.

Проверка: **77 автоматизированных тестов** включая MAX, дополнительно тест открытия интерфейса. Настоящая отправка в MAX с твоими реквизитами и запуск на Windows пока не проверены.

## Задание «Тестирование и исправление 1С 8»

Разделы: «Подключение к базе», «Отключение пользователей», «Тестирование», «Выполнить команды», «Расписание автозапуска», «Прервать выполнение».

Реализация через штатный пакетный режим Конфигуратора:

    1cv8.exe DESIGNER /S<сервер>\<база> /IBCheckAndRepair ... /Out <журнал>

Вкладка «Тестирование»:

- Реиндексация таблиц `-ReIndex`
- Проверка логической целостности `-LogIntegrity`
- Проверка ссылочной целостности `-LogAndRefsIntegrity` (взаимоисключающий режим с `-LogIntegrity`)
- Пересчёт итогов `-RecalcTotals`
- Сжатие таблиц `-IBCompression`
- Реструктуризация таблиц `-Rebuild`
- Только тестирование `-TestOnly` — **режим по умолчанию**
- Тестирование и исправление — нужно явно выбрать и подтвердить
- Политика неисправных ссылок: без изменения / создание / очистка
- Политика частично потерянных объектов: без изменения / создание / удаление
- Время выполнения — `-TimeLimit:ЧЧЧ:ММ`

При запуске исправления программа:

1. Проверяет, что режим исправления явно разрешён.
2. Для серверной базы через RAS блокирует новые сеансы, отключает регламентные задания и ожидает выхода пользователей (после ожидания может завершить сеансы согласно настройке).
3. **До исправления делает новую локальную `.dt` копию**. Проверяет её ненулевой размер и SHA256. Если копия не получилась, исправление **не запускается**.
4. Вызывает `/IBCheckAndRepair` с выбранными параметрами.
5. Независимо от результата пытается снять блокировку RAS и восстановить исходное состояние регламентных заданий.

Для файловой базы нужен выход всех пользователей, который программа автоматически не гарантирует. При запуске исправления требуется отдельная отметка «все пользователи вышли».

**Важно:** контроль размера и SHA256 не доказывает успешность будущего восстановления. Для критичных баз рекомендуется заранее проверить восстановление `.dt` в тестовой среде.

## Задание «Вызов процедуры 1С 8»

В списке процедур есть наименования «Выполнение обмена» и «Внешняя обработка». Фактический запуск выполняется через заранее подготовленный **внешний файл `.epf`**:

    1cv8.exe ENTERPRISE /S<сервер>\<база> /Execute C:\Scripts\Exchange.epf /C "mode=auto"

**Универсального вызова произвольной процедуры конкретной конфигурации 1С нет.** Для обработки обмена нужен `.epf` с кодом обмена, совместимым с вашей конфигурацией. Внешняя обработка должна самостоятельно завершать свою работу и закрывать сеанс 1С после выполнения; иначе она будет остановлена по таймауту задачи.

По умолчанию процесс **не отключает** других пользователей. Включить эксклюзивный режим можно отдельной галочкой. Для серверной базы используется тот же механизм RAC с обязательным снятием блокировки.

## Версия платформы

Режимы: автоматический / ранее сохранённый / вручную `1cv8.exe`. В авто-режиме ищутся установленные версии **8.3, 8.5 и другие установленные версии 8.x** (в каталогах `Program Files\1cv8`). Внешний стартер `1cestart.exe` не подменяет выполняемый `1cv8.exe` в пакетных заданиях.

## Сборка Windows EXE

1. Для сборки установите Python 3.11–3.13.
2. Распакуйте исходники.
3. Запустите `build_windows.bat` (или `build_windows_folder.bat` для сборки в папку).
4. Готовый `dist\1CBackupManager.exe` заменяет старый, **но не заменяйте и не удаляйте** существующие `config.json`, `secrets.dat`, `scheduler_state.json`.
5. До обновления остановите Windows-службу `OneCBackupManager`, закройте GUI, сделайте резервную копию старого EXE и конфигурации.
6. Проверьте тестовую задачу, только затем включайте ночное расписание.

Рабочие задачи `.dt`, MS SQL, файлов, ZIP/7z, FTP/FTPS, Telegram, SMTP, системный трей, статус агента оставлены.

## Проверка

Автоматизированные тесты: `pytest -q test_v4.py test_v41.py test_v43.py test_v44.py test_v45.py test_v46.py`.
Тест интерфейса: `xvfb-run -a -s '-screen 0 1920x1080x24' python smoke_v46.py` (на Linux для проверки компоновки).

Реальное выполнение ТиИ или `.epf` на рабочем сервере Windows в данном окружении не проверялось. Сначала испытайте эти сценарии на копии информационной базы.
